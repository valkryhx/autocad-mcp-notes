> 分析日期：2026-11-19

> 生成脚本：`scripts/gen_20261119_room_plan.py`
> 用途：作为**机房类平面布置图**的参考范例。下次画同类图（数据中心、设备机房、机柜排布）时，制式和版面可直接照搬。

## 1. 一句话概括这张图的做法

**A2 图幅 @ 1:50，左侧放一个 2×2 房间的平面图，右栏自上而下竖排四块内容（设计说明 / 单柜详图 / 配置表 / 标题栏），每块占满栏宽、互不交叠。**

这个"左图右栏、右栏竖向铺满"的式样是关键。1:50 下建筑只有 16680×13080，用 A1 会让平面只占图纸 44% 宽、右侧大片空白（这张图第一版就是 A1，实测后改成 A2）。

## 4. 图层制式

11 个工程图层，命名用 `A-` 前缀 + 中文出图习惯的功能名。**线宽全部显式指定，不用 Default(-3)。**

| 图层 | 颜色 | 线宽 | 线型 | 实体数 | 用途 |
|---|---|---|---|---|---|
| A-FRAME | 7 白 | 50 | Continuous | 2 | 图框（外框 + 内框） |
| A-WALL | 7 白 | 50 | Continuous | 2 | 外墙（外皮 + 内皮双线） |
| A-WALL-IN | 7 白 | 35 | Continuous | 2 | 内隔墙 |
| A-RACK | 4 青 | 25 | Continuous | 82 | 机柜（80 柜 + 详图 + 图例） |
| A-GPU | 30 橙 | 18 | Continuous | 812 | GPU 格位分隔刻度 |
| A-CHANNEL | 3 绿 | 18 | **DASHED** | 5 | 封闭冷通道 |
| A-TEXT | 7 白 | 18 | Continuous | 149 | 文字 |
| A-DIM | 2 黄 | 13 | Continuous | 4 | 尺寸标注 |
| A-TITLE | 7 白 | 35 | Continuous | 10 | 图名 / 标题栏 / 各块标题 |
| A-TABLE | 7 白 | 18 | Continuous | 10 | 配置表网格 |
| A-EQUIP | 2 黄 | 35 | Continuous | 0 | 预留（设备层） |

**线宽层次**（ISO 128 的粗/中/细三级）：

```
50 (0.50mm) 图框、外墙      ← 最粗，压住画面
35 (0.35mm) 内隔墙、图名、   ← 次粗，块标题
25 (0.25mm) 机柜            ← 中，主体设备
18 (0.18mm) 文字、表格、通道 ← 细，辅助
13 (0.13mm) 尺寸            ← 最细
```

**为什么锁这些值**：`drawing_critique` 的 `property_override` 检查会把非 ByLayer 的线宽列为错误；而 `-3` 是 Default 不是 ByLayer（`-1` 才是）。这里全部显式写在图层上，实体一律 ByLayer。

|---|---|---|---|
| 380 | 7.6 mm | 1 | 大标题「20261119 GPU 机房平面布置图」 |
| 250 | 5.0 mm | 4 | 房间名「机房 A/B/C/D」 |
| 220 | 4.4 mm | 1 | 标题栏内图名 |
| 200 | 4.0 mm | 1 | 块标题「设计说明」「机房配置表」 |
| 190 | 3.8 mm | 3 | 「图例」「单柜详图  1:25」「设计说明」 |
| 140 | 2.8 mm | 15 | 说明正文行、图例条目、详图旁注、标题栏字段 |
| 135 | 2.7 mm | 1 | 设计说明 MTEXT 正文 |
| 130 | 2.6 mm | 30 | 配置表单元格 |
| 125 | 2.5 mm | 92 | **机柜编号（主体）**、房间配置行、排号 |
| 110 | 2.2 mm | 1 | 「（前维护面）」 |
| 70 | 1.4 mm | 6 | 详图里的 GPU-01..06 |

**规律**：主体标注（柜号）用 **2.5 mm 纸面**，正是 ISO 3098 的下限值；再小就会触发 `text_illegible` 检查。层级按 1.25–1.5 倍递增，不是随手取的。

### 5.2 字体

```python
DOC.styles.add("CN", font="simhei.ttf")
```

**必须用单体 `.ttf`，不能用 `.ttc` 集合字体**（`simsun.ttc` 在用 AutoCAD 出 PDF 时无法嵌入，中文会被炸成几何线条，PDF 里 `Tj` 指令为 0）。

`Standard` 样式的 `txt.shx` **没有 CJK 字形**，中文存得进去、读得回来、屏幕上什么都不显示，且不报错。所以每个 TEXT 都显式带 `style="CN"`。

`m²`、`Ø`、`±`、`°` 同理 —— 用 TrueType 时**直接写 Unicode 字符，不要写 `%%d`/`%%c`**，那是 SHX 专用控制码。

### 5.3 对齐方式

```python
ent.set_placement((x, y), align=TextEntityAlignment.MIDDLE_LEFT)   # 左对齐、垂直居中
```

这张图用了 `MIDDLE_LEFT`（图名、图例、说明、旁注）和 `MIDDLE_CENTER`（柜号、房间名、表格单元格）。

⚠️ **不要把文字留在混合对齐态**（如 `halign=0` + `valign=2`）。DXF 里合法，但 AutoCAD 存 DWG 时会按垂直对齐码重算插入点（下移半个字高），导致同一个文件 DXF 和 DWG 测出不同的文字框。详见 [`docs/20261119-text-anchor-group10-11.md`](../../docs/20261119-text-anchor-group10-11.md)。

### 5.4 排版铁律

**文字一律排在几何之外或几何特意留出的空白带内，不靠"检查器兜底"。**

这张图做到 0 条交叠，是因为生成时就按这个原则排：
- 柜号竖排 90° 放柜中线，GPU 分隔刻度只画在柜内两侧各 90 长，中间留出 240 宽的空白带给文字
- 房间名和配置行放冷通道正中，两行间距 400（远大于两行半高之和 188）
- 图例、说明、表格各自占独立区块

## 6. 平面图几何构成

### 6.1 建筑

```
外墙厚 240，内隔墙 200
建筑外轮廓  16680 × 13080
建筑内轮廓  16200 × 12600   （外皮内缩 240）
2×2 四个房间，单房内净 8000 × 6200
```

画法：**外墙用双线**（外皮 + 内皮两条闭合 LWPOLYLINE），内隔墙同样双线。这样在平面图上能直接看出墙厚。

### 6.2 机柜排布（实测反推）

| 项 | 值 |
|---|---|
| 机柜尺寸 | 600 × 1200 |
| 每排柜数 | 10 |
| 一排长度 | 6000 |
| 每房排数 | 2（面对面） |
| 冷通道净宽 | **1800**（实测：两排 Y 起点差 3000 − 柜深 1200 = 1800） |
| 排距（中心到中心） | 3000 |
| 后走道 | 1000 |
| 侧走道 | 1000 |
| 全场合计 | 4 房 × 2 排 × 10 柜 = **80 柜** |

**实测的四排 Y 起点**：`5620, 8620 | 12020, 15020` —— 相邻两房之间是横向内隔墙（200 厚）。

### 6.3 单柜 6 GPU 的表达方式（关键制式）

这是这张图最需要照搬的技巧：**用短刻度表达格位，而不是通长分隔线**。

```python
# 每柜 6 格 = 5 条分隔线；每条只画柜内两侧各 90 长
for g in range(1, 6):
    gy = yb + g * 200              # 1200 / 6 = 200 格距
    line(x0 + 60, gy, x0 + 60 + 90, gy, "A-GPU")          # 左侧刻度
    line(x0 + 540 - 90, gy, x0 + 540, gy, "A-GPU")        # 右侧刻度
```

如果画通长分隔线，柜号（竖排、占柜宽中线）必然被线穿过 —— 实测第一版报了 **39 处 text_curve**。改成短刻度后归零。

**刻度参数**：
- 从柜内壁 60 处起，长 90
- 两侧各一段，中间留 240 净宽（柜宽 600 − 60×2 − 90×2 = 300，再扣掉文字宽度约 60）
- 格距 200（= 1200 / 6）

### 6.4 封闭冷通道

用 `A-CHANNEL` 图层 + `DASHED` 线型画矩形框，包住两排机柜之间的 1800 净宽区域。

### 尺寸样式 ISO50

```python
dimstyle = DOC.dimstyles.duplicate_entry("EZDXF", "ISO50")
dimstyle.dxf.dimtxt = 2.5       # 纸面字高 mm
dimstyle.dxf.dimasz = 2.0       # 箭头 mm
dimstyle.dxf.dimexe = 2.5       # 尺寸界线超出
dimstyle.dxf.dimexo = 2.0       # 尺寸界线偏移
dimstyle.dxf.dimgap = 1.0       # 文字与尺寸线间隙
dimstyle.dxf.dimdec = 0         # 小数位
dimstyle.dxf.dimscale = 50.0    # 放大到模型空间
dimstyle.dxf.dimlfac = 1.0      # ⚠️ 必须显式设 1.0
```

⚠️ **`dimlfac` 必须显式设 1.0**。`EZDXF` 模板里它是 **100**（给模板自带的毫米/厘米示例用的），继承过来会把 16680 显示成 **1668000**。`drawing_critique` 的 `dim_dimlfac_scaled` 会抓到这一点。

**验证标注是否正确，要读 `*D` 块里的实际文字**，不能读 `Measurement` 属性（pywin32 下它要求写模式，读不了）：

blk = doc.blocks.get(dim.dxf.geometry)
actual_text = [t.text for t in blk if t.dxftype() == "MTEXT"]   # ['16680']

## 8. 右栏三块的做法

### 8.1 设计说明（MTEXT）

```python
mt = mtext("1. ...\n2. ...", NT_X, NT_Y + 1250, 135, width=NT_W)
mt.dxf.line_spacing_factor = 1.6
```

- 用 **MTEXT** 而不是多个 TEXT：行距用 `line_spacing_factor` 统一控制
- `width` 设成栏宽（到版心右缘），让长行自动换行
- `line_spacing_factor = 1.6` 比默认宽松，中文说明更易读

**MTEXT 高度算法**（验证时用）：`总高 = 单行墨迹高 + 字高 × 5/3 × (行数-1)`。默认组码 44 = 1.0 时 AutoCAD 用 "3-on-5" 行距，即 5/3 字高，不是 1 倍。

### 8.2 单柜详图（1:25）

- 放大倍数 `K = 2.0`（相对平面 1:50 → 详图 1:25）
- 柜框 1200 × 2400，6 格分隔用**通长线**（详图里可以，因为没有柜号文字压在上面）
- 每格中心标 `GPU-01..06`，字高 70（纸面 1.4 mm —— 详图是 1:25，实际纸面 = 70/25 = 2.8 mm）
- 旁注三行放详图右侧，与详图本身 Y 跨度对齐

### 8.3 配置表（网格线 + TEXT）

**不用原生 AcDbTable**，理由：

```text
ezdxf 1.4.4 没有 TABLE 写出 API（add_table 不存在）
原生 AcDbTable 只能经 AutoCAD COM 的 AddTable 建
而 COM 在长流水线里反复出现 RPC/保存失败、文件锁、<unknown>.Count
建表这一步成了整条流程最脆的环节
```

用网格线画的表在 DXF 里是普通 LWPOLYLINE + TEXT，**任何引擎都能读写，文字照样进得了交叠检查**（原生 TABLE 的单元格在 `*T` 块里，检查反而更绕）。

**做法**：

```python
TB_COL_W = (1700, 1500, 1700, 1700, 1800)   # 合计 8400，铺到版心右缘
TB_ROW_H = 380
TB_TXT_H = 130

rect(TB_X, TB_Y - TB_H, TB_X + TB_W, TB_Y, "A-TABLE")    # 外框
# 横向分隔
cy = TB_Y
for r in range(1, len(TB_ROWS)):
    cy -= TB_ROW_H
    line(TB_X, cy, TB_X + TB_W, cy, "A-TABLE")
# 纵向分隔
cx = TB_X
for c in range(1, len(TB_COL_W)):
    cx += TB_COL_W[c - 1]
    line(cx, TB_Y, cx, TB_Y - TB_H, "A-TABLE")
# 单元格文字：居中，行高 380 ≫ 字高 130
for r, row in enumerate(TB_ROWS):
    cy = TB_Y - r * TB_ROW_H - TB_ROW_H / 2
    cx = TB_X
    for c, val in enumerate(row):
        txt(val, cx + TB_COL_W[c] / 2, cy, TB_TXT_H, "A-TEXT")
        cx += TB_COL_W[c]
```

**锚点是左上角，表格向下生长**。表标题必须写 `TB_Y + 500`（贴表头上方），写成 `TB_Y + TB_H + 500` 会让标题浮在表格上方 2780 处、与表格脱开 —— 这是实际踩过的 bug。

## 9. 验收流程（这张图的完整验证链）

改完之后按这个顺序验，任一项不过就不算完成：

| # | 检查 | 命令 | 本次结果 |
|---|---|---|---|
| 1 | 几何实测（逐柜归属统计，不看总数） | `python scripts/verify_20261119.py` | 19/19 通过 |
| 2 | **文字交叠（DXF）** | `python -m tools.text_overlap X.dxf` | 0 findings |
| 3 | **文字交叠（DWG）** | `python -m tools.text_overlap X.dwg` | 0 findings |
| 4 | 版面块级重叠 + 越框 | `python scripts/check_20261119_layout.py` | 无交叠无越框 |
| 5 | 负对照（植入缺陷确认检查器有效） | 在副本上植入 4 类缺陷 | 全部检出 |
| 6 | 真实窗口截图看中文 | AutoCAD 窗口截图 | 中文正常 |

### 三个容易漏的点

**① 文字交叠必须 DXF 和 DWG 都跑。** DXF 是"我要写的"，DWG 是"AutoCAD 认的"。两者不一致就说明有一方的读法是错的 —— 这张图就因此查出检查器把 TEXT 的组码 10/11 读反了（详见 `docs/20261119-text-anchor-group10-11.md`）。

**② 0 findings 不等于图没问题。** 它只说明"检查器读到的这些实体之间没有碰撞"，不判断几何对不对、标注是否与实际一致、版面是否失衡。

**③ 检查器要能抓到问题才算证据。** 报 0 之后，在副本上植入压字、压线、隐藏层、重复四类缺陷，确认全部检出，才能相信这个 0。

### 判断数学是对的，不是重念一遍输入

`verify_20261119.py` 的做法（值得照搬）：

- 柜数不是数 `add_lwpolyline` 调了几次，而是**读回每个 600×1200 矩形的实际位置**，再按房间内轮廓判定归属
- 每柜格数不是假设，而是**把 A-GPU 刻度按坐标归属到具体柜**，再数每个柜有几档、每档几段
- 柜号位置不是信任写入值，而是**从文字框坐标反推**，与柜中心比对
- 对齐锚点不是信任写入值，而是**在 DWG 上重新测量**

第一版校验脚本把 OX/OY 和图幅硬编码，改版面后报出 5 条假 FAIL；后来改成从生成脚本读取参数。**校验器的常量必须与生成器同源。**
